# Security Policy

## Supported versions

Security fixes are applied to the latest released version. Users should update to the latest version before reporting an issue.

## Reporting a vulnerability

Do not disclose vulnerability details in a public GitHub issue.

Use the repository's **Security** tab to submit a private vulnerability report. If private reporting is unavailable, open a public issue containing only a request for private contact and no technical, exploit or customer information.

Include, where possible:

- The affected plugin and WordPress versions.
- The affected Elementor and Elementor Pro versions.
- Clear reproduction steps.
- The expected and observed behaviour.
- The security impact.
- Any suggested remediation.

Reports will be reviewed before public disclosure. Please allow time for verification, remediation and release preparation.

## Scope

Relevant reports include authentication or authorization bypasses, cross-site scripting, request forgery, injection, sensitive-data exposure and email-header injection caused by this plugin.

Delivery failures, Elementor Pro vulnerabilities and hosting or SMTP configuration issues should be reported to the responsible product or service provider.
